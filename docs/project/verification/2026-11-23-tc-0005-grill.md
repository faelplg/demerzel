## Findings

1. **Minor - T4 against the partial-confirmation tests and output 8.**

   **Finding:** T4 accepted a `tab create` answer only when its tab and root pane IDs agree and name the recorded workspace, and recorded nothing otherwise. Today `reportSession` in `src/herdr/backend.ts` records the resources a partial creation answer confirms before failing, and the tests for findings K2 and L2 of the TC-0002 verifications in `test/herdr/backend.test.ts` (no tab, no root pane, no workspace object, with and without a lost reconciliation snapshot) depend on it. Output 8 did not allow those tests to change. The contract had to choose between all or nothing and recording a tab from a partial answer.

   **Applied:** T4 is all or nothing. `tab.tab_id`, `root_pane.tab_id`, `root_pane.pane_id`, `tab.workspace_id` and `root_pane.workspace_id` must all be present as non-empty strings, the two tab IDs equal, and both workspace IDs equal to the recorded workspace, before the tab and the pane are recorded. A `workspace` object is not expected, since herdr 0.9.5 sends none. A partial or contradictory answer records nothing; the failure path finds the tab by its unique task label, and with that snapshot lost too, a later `close` finds it by label (X1). Output 8 now lists the partial-confirmation tests and says how they are rewritten, including "without the workspace object" becoming "without `tab.workspace_id`". A mutation was added for recording a partial answer. This is the option the owner preferred: no resource recorded without confirmation, and it matches what herdr 0.9.5 returns.

2. **Minor - exact history details for `tab-found`, `close-failed` and `closed`.**

   **Finding:** X1, X2, X4 and EB-07 did not fix the history detail shapes that replace today's `workspace-found` `{ workspace, by: "label" }`, `close-failed` `{ workspace, backend_error }` and `closed` `{ workspace_closed }`.

   **Applied:** X1 fixes `tab-found` as `{ tab: <found tab ID>, by: "label" }` and says `backend_ids.pane` is left as it is, also when `null`, and `created` is not changed by `close`. X2 fixes `close-failed` as `{ tab, backend_error }` and `closed` as `{ tab_closed, last_tab_in_workspace }`, with `tab_closed` `null` when no call was made. X4 says `last_tab_in_workspace` is `false` when another tab remains or the task's tab was not in the snapshot. The EB-07 row asks for whole-detail assertions.

3. **Minor - Portuguese `next` for `herdr.workspace_labels` refusals.**

   **Finding:** `src/cli/run.ts` wraps every `parseHerdrConfig` failure with the Portuguese `next` "Corrija o bloco herdr da configuração e rode de novo.", so a new English message would reach the user with a Portuguese `next`, against E1.

   **Applied:** output 6 now includes an English `next` for every `parseHerdrConfig` refusal in `src/cli/run.ts`, already in the allowed scope, which section 4 now names; C1 and E1 point to it. The existing `test/cli.test.ts` only asserts the code `config-invalid`.

4. **Nit - control characters in `herdr.workspace_labels` keys.**

   **Finding:** C1 forbade control characters in values only, and an offending key named in a message could break the line-oriented text output.

   **Applied:** C1 forbids U+0000 to U+001F and U+007F in keys too, and names an offending key with `JSON.stringify`. A mutation was added for both.

5. **Nit - test annotations in section 4.**

   **Finding:** section 4 annotated `test/herdr/` only with "see the exception in output 8", although outputs 7 and 10 also change it, which made acceptance criterion 13 read as if it covered `scenario.ts` and `smoke.ts`.

   **Applied:** section 4 annotates `test/core/` and `test/cli.test.ts` with outputs 7 and 8 and `test/herdr/` with outputs 7, 8 and 10. Output 8 and acceptance criterion 13 now cover only the tests that exist at the entry commit, other than `scenario.ts` and `smoke.ts`.
