## Changed

`src/core/backend.ts`, `types.ts`, `workspace.ts` and `tab.ts` define the
per-tab snapshot, pure workspace resolution, immutable recorded workspace
and shared scoped ownership fallback. `commands/dispatch.ts` resolves before
the task lock and every write; `commands/common.ts` recovers confirmed tabs;
`commands/close.ts` refuses foreign candidates before publication, closes
only the unit tab and records exact history and last-tab details.

`src/herdr/config.ts` validates the optional user mapping without reading its
paths or echoing values. `src/cli/run.ts` supplies its English next action.
`src/herdr/backend.ts` creates tabs in the recorded workspace, confirms tab
and pane atomically, validates tab relations and selects agent panes per tab.
Claude Code retains the main checkout cwd and printing hook; Codex retains
the prepared worktree cwd and startup update override. The fake backend and
fake herdr model human tabs, several unit tabs, per-tab agents and tab close.

README setup, configuration and close guidance match the new behavior.
The isolated real-herdr scenario covers the workspace and tab lifecycle.
The smoke now creates its project workspace, launches both harnesses as
concurrent tabs, checks both working and checks each close preserves its
neighbors. It was updated but not executed by the Build.

## Engineering notes

The lookup and fallback are small pure core helpers used through the Backend
port; the core does not import the adapter or inspect its config. No dependency,
permission/trust flag, focusing operation, automatic workspace creation,
placeholder tab, task migration or re-launch was added. Configuration keys
are validated syntactically and never resolved or checked for existence.
The real scenario's tab-created result and snapshot validate the fake's
normal handshake and the last-tab behavior against herdr 0.9.5.

The completion readback checks registry project_workspace, backend_ids and
created in the two-unit core test, including persisted JSON. Spec and Plan
were reviewed against output 1. Existing tests changed only by output 8;
scenario and smoke changes follow output 10. All read-only paths remain
identical to entry. The read-only contract `docs/project/contracts/TC-0005-herdr-tabs.md` is unchanged.

## Remaining limitations

- A human can leave a unit as the workspace's last tab. Closing it can
  remove the workspace in herdr; the next dispatch refuses until recreated.
- Workspace selection is recorded before preparation. Removal during
  preparation fails launch after the branch and worktree already exist.
- Symlink keys in workspace_labels never match the main checkout real path.
  A missing-workspace refusal names that real path.
- Two identical task tab labels in one workspace refuse every snapshot
  until the human removes a duplicate; the same label elsewhere is valid.
- An empty human tab with the exact task label in the recorded workspace
  cannot be distinguished from a pre-agent-start tab. It is recoverable
  and closable by that task, as F4 explicitly requires. Foreign agents refuse.
- Pre-0.19 tasks are not migrated. Their recorded tab is closed, possibly
  emptying the legacy workspace; half-done tasks have no label fallback.
- Tab operations were tested on herdr 0.9.5. Only tab create was previously
  observed on 0.9.0; a snapshot missing labels fails safe. Minimum stays 0.9.0.
- CI, authenticated harness smoke and cross-vendor re-verification remain pending.
  The supplied independent FAIL verdict remains recorded; optional smoke
  concurrency timing behavior is unchanged, as detailed in the follow-up.
  The orchestrator must add their evidence and decide contract acceptance.
